# Veloura Lucent — Stem Mode 実装資料

## 0. 文書の位置付け

### 0.1 目的

本書は、Veloura LucentにStem Modeを実装するための仕様、承認境界、実装順序、検証方法、進捗確認方法を定める。

Stem Modeは通常モードとは別画面で使用する。

ただし、Stem Mode画面の内部は通常モードの画面構成、操作方法、段階的処理、試聴、解析、設定、進捗、ログ、一時保存、品質確認、書き出しを基礎とする。

Stem Modeだけ異なるアプリ、異なる操作体系、異なる簡易処理として設計しない。

### 0.2 正本とする情報

仕様判断では、次の順で根拠を扱う。

1. ユーザーが明示的に承認した内容
2. 現行通常モードの実コードと呼び出し関係
3. 現在のworktreeとビルド・テスト結果
4. モデル・Apple API・依存ライブラリの一次資料
5. README

READMEは補助資料であり、実コードと異なる場合は実コードを正本とする。

### 0.3 チェックの付け方

- `[x]`は、指定された完了根拠を確認した項目だけに付ける。
- コードが存在するだけでは実装完了にしない。
- ビルド成功、テスト成功、実画面確認、実音確認は別々に判定する。
- 過去に成功したテストでも、現在のworktreeで成立しなければ完了扱いにしない。
- 未確認事項を推測で完了にしない。
- ユーザー判断が必要な場合は実装を停止し、確認後に再開する。

### 0.4 2026-07-28 再ミックス工程の確定

ユーザー承認により、Stem Modeの処理境界を`補正 → 再ミックス → マスタリング`の3段階へ更新した。本項は、本書内に残る旧二段階記録と「補正後再ミックス」を純粋加算と同義に扱う過去記述より優先する。

- 補正段は補正済み4Stemと、gain、pan、reverb、normalization、dynamics、limitingを行わない補正済み純粋加算を保存し、`readyForRemix`で停止する。
- raw Stemは補正比較、自動値算出、明確な極性反転時の局所fallbackに保持する。
- ドラムのトランジェント回復は、rawと補正済みStemの同じ時間位置を比較し、rawに実在する不足成分だけをraw sample包絡線内で戻す。
- 再ミックス段は、今回のraw／補正済みStemから作る自動値と、ユーザーが手動に切り替えた項目だけの上書きを使う。同じセッションで自動値を更新しても手動上書きを保持し、新しい補正セッションを開始した時だけ両方を初期化する。
- 自動panはraw／補正済みStemの同じ20 ms活動区間における左右中心差を比較し、中央50%の差が同じ方向へ揃い、画面の中央表示境界`0.005`以上である時だけ適用する。方向が揃わない、差が小さい、または有効区間が不足する場合は`0`とする。
- 再ミックス処理順は、Stem別gain、pan前の条件付き帯域ducking、Stem別pan、pan後のStem別send、1基の減衰制御・拡散付き共有reverb、dry加算、return加算、構造検証である。
- drums／bassとvocals／otherの帯域duckingは、有効・無効と処理量を別々の自動値・手動上書きとして持つ。手動で無効にしても処理量を保持し、再度有効にした時に同じ量を使う。
- 純粋加算Aと再ミックスBを画面上でA/B試聴する。ラウドネス合わせは再生時だけで、保存音声を変更しない。
- 再ミックス段で固定-3 dB、normalization、saturation、limitingを行わない。まとまりと最終True Peak保護は既存マスタリングで1回だけ行う。
- 再ミックス設定変更、失敗、キャンセルでは、再ミックスと最終版だけを無効化し、補正済み4Stemと純粋加算を保持する。
- マスタリングは検証済み`stem-remix-48000.wav`だけを受け付ける。
- 通常モードの補正・マスタリング経路と通常モード画面には、このStem専用工程を追加しない。

## 1. 目的と優先順位

### 1.1 処理目的

通常モードの概略は次のとおりである。

```text
入力2mix
→ ノイズ除去
→ 補正
→ 補正済み一時ファイル
→ マスタリング
→ 最終2mix
→ ユーザー操作による書き出し
```

Stem Modeでは、これを次へ拡張する。

```text
入力2mix
→ 4Stem分離
→ Stem別ノイズ除去
→ Stem別補正
→ 補正済み4Stem
→ 補正済み純粋加算
→ 自動値算出・任意の手動上書き
→ Stem別gain／pan・条件付き帯域ducking・共有reverb
→ Stem再ミックス
→ 既存マスタリング
→ Stem Mode最終版
→ ユーザー操作による書き出し
```

### 1.2 優先順位

優先順位は次のとおりとする。

1. 通常モードの音質・動作を変えない
2. 音楽成分を失わない
3. 通常モードと同等以上の音質を目指す
4. 同じ入力・設定・seedで再現可能な処理にする
5. 性質の異なる入力へ対応できる汎用性を持たせる
6. 実用的な処理速度とメモリ使用量にする

1曲だけを基準に固定閾値や固定補正値を決めない。

処理対象はユーザーが生成・所有するAI生成音楽を中心とするが、1曲専用の処理にはしない。

### 1.3 現段階で必須としないもの

- App Store公開
- Developer ID配布
- 公証
- 不特定多数向け商用サービスとしての証明
- isolated stem corpus
- 通常モード最終版との必須比較
- 16通りの完成候補生成
- Stem Mode専用の補正候補生成・候補比較・品質選択
- AIによるStem品質評価・補正結果選択
- ウィンドウ単位の処理状態仕様
- 自動ミックスバランス調整
- 自動パン
- Stem別マスタリング
- raw再ミックスのユーザー書き出し
- No vocals成果物
- Core ML版

## 2. 通常モードの実コード上の仕様

### 2.1 画面全体

通常モードは次の領域で構成される。

| 領域 | 役割 |
|---|---|
| 上部 | 入力、補正、マスタリング、書き出し |
| 左サイド | 音源と補正・マスタリング工程 |
| 中央 | 基本表示、詳細解析、詳細ログ |
| 右上 | 補正値、マスタリング値、アプリ設定 |
| 右下 | 選択音源の主要4値、品質警告、完了後レポート |
| 下部 | 直近ログと全体工程 |

通常モードとStem Modeは、`VelouraRootView`が所有する同一のワークスペース外枠を使用する。外枠は上部toolbar、左サイド、中央、右インスペクタ、中央下部を一度だけ組み立て、モード切り替えでは各領域へ渡す内容だけを交換する。

画面幅は次の契約とする。

- 左サイド：`NavigationSplitView`の通常モード既存契約と同じく、最小220 pt、基準260 pt、最大300 pt
- 中央：620 pt以上で残り幅を使用
- 右インスペクタ：440 pt固定
- 左右の表示・非表示はRootで保持し、モード切り替えで作り直さない
- `NavigationSplitView`はRootの共通外枠に1個だけ置き、モード別の分割View、列幅状態、幅履歴、座標補正を追加しない

これにより、通常／Stem切り替えで分割Viewを作り直さず、通常モードと同じ左サイドの幅範囲とシステムサイドバーの外観を両モードで使う。

### 2.2 上部操作

通常モードの上部操作は次の4種類である。

- 音声を選ぶ
- 補正を実行／キャンセル
- マスタリングを実行／キャンセル
- 補正後または最終版を書き出す

補正とマスタリングは別ユーザー操作である。

入力ファイルの選択またはドラッグ＆ドロップが確定した時点で、補正操作を待たずに、選択した入力2mixの表示・試聴用解析を開始する。入力2mixの波形、再生、スペクトログラム、主要測定値は、この入力選択時解析の実データへ接続する。

入力選択時解析は補正workflowと別の処理である。解析中でも通常モードと同様に補正を開始でき、補正開始によって入力選択時解析を中断・消去しない。補正キャンセル後も、選択中の入力音源、入力解析の状態と結果、波形、再生対象を維持する。これらを破棄するのは入力変更が確定した時だけとし、変更前入力の非同期解析結果を変更後入力へ反映しない。

補正workflow内で行う分離用44.1 kHz信号の生成と処理判断用評価は、入力選択時の表示・試聴用解析とは別である。前者を理由に、入力解析の開始を補正操作後まで待たせない。

### 2.3 左サイドバー

左サイドバーは「音源」と「工程」を表示する。

音源：

- 入力音声
- 補正後
- 最終版
- ファイル名
- パス
- 音声形式
- サンプルレート
- 再生時間

工程：

「工程」は項目を横並びまたは同じ階層で列挙する表示ではない。

上から「補正」と「マスタリング」の2つの処理ブロックを縦に置き、間を区切り線で分ける。

各処理ブロックの内部には、次を一体として表示する。

- 状態アイコンと処理名
- 開始後の経過時間
- 現在実行中の工程名。実行中でなければ処理全体の状態
- 実行中工程の詳細
- 進捗バーと進捗率
- その処理に含まれる全工程の縦一覧

各工程の状態は、次のアイコン、色、必要な場合の短いラベルで表す。

- 待機：空の丸。文字ラベルは付けない
- 実行中：点入りの丸と「実行中」
- 完了：チェック。文字ラベルは付けない
- 省略：マイナスと「省略」
- 失敗：バツと「失敗」

実際の画面表示は「スキップ」ではなく「省略」である。

「省略」は、通常モードと同じく、今回のStem解析から確定したrouteが当該工程を不要と判断した場合だけに使用する。DSP失敗、出力構造不正、Stem役割別guardの不確実に対して、当該DSPの処理直前Stemを安全に維持して次工程へ進めた場合は、その工程を「完了」とする。理由は詳細ログとguard記録へ残す。安全な処理直前Stemも維持できず、次工程へ渡せる音声を確定できない場合だけ「失敗」とする。

下部の「入力解析、補正処理、マスタリング、書き出し」という4段階の全体進捗は、左サイドバーの工程表示とは別である。

### 2.7 右インスペクタ下部

右下は3つの設定タブから独立した「解析結果と品質確認」である。

選択した入力／補正後／最終版について、次の4項目を要約表示する。

- Integrated Loudness
- True Peak
- ダイナミクス
- ステレオ幅

加えて、

- 品質警告
- 調整候補
- 完了後レポートを開くボタン

を表示する。

完了後レポートはポップオーバーで表示する。

選択音源が未解析の場合は、大きな空表示で設定欄を圧迫せず、アイコン、未解析状態、次に必要な操作だけを小さく表示する。

### 2.8 下部と詳細ログ

下部左は直近ログ、下部右は全体工程である。

直近ログは、通常モードと同じく、入力、補正、マスタリング、ユーザー書き出しの操作単位で構造化した最大4件を表示する。内部ログの末尾4行をそのまま表示しない。

全体工程は次の4段階である。

1. 入力解析
2. 補正
3. マスタリング
4. 書き出し

全体工程の「書き出し」は、アプリ内部の一時ファイル生成やStem Mode最終版生成を意味しない。補正後成果物またはStem Mode最終版が存在する間は「保存可能」とし、ユーザーが保存先を選び、外部ファイルへの書き出しに成功した後だけ「保存済み」とする。

詳細ログを開くと、中央画面が補正ログとマスタリングログの表示へ切り替わる。

詳細ログでは、工程状態を更新する制御イベントと人が読むログを分離する。制御イベントをログ本文へ表示せず、実行した主要工程を短い人向けの行として実行順に生成し、補正ログとマスタリングログへ分けて表示する。

## 3. 通常モードを保護する境界

### 3.1 変更禁止対象

Stem Modeのために、通常モードの次を変更しない。

- 解析条件
- ノイズ判定
- 補正量決定
- DSP順序
- guard条件
- 許容範囲
- fallback条件
- マスタリング処理
- ラウドネス処理
- ダイナミクス処理
- ピーク制御
- 品質評価
- 通常モードの音声ファイル入出力
- 通常モードのサンプルレート変換
- 通常モードの表示値と処理値の接続

通常モード側へStem用条件分岐を追加しない。

### 3.2 共用可能な汎用処理

次は、音質判断を変えない場合に限り共用できる。

- ファイル入出力補助
- 一時ファイル管理
- 進捗イベント型
- ログ表示部品
- 共通エラー型
- 表示専用部品
- 汎用音声データ構造
- 再生・A/B比較部品
- グラフ表示部品

### 3.3 既存音質処理の利用方法

既存解析器、下位DSP、guard、品質評価、マスタリングは再利用を優先する。

ただし通常モード側を書き換えてStem対応させない。

実装前に各資産を次へ分類する。

| 分類 | 対応 |
|---|---|
| 既存公開APIから直接利用可能 | Stem専用側から呼ぶ |
| Stem専用adapterで利用可能 | adapterをStem専用ファイルへ実装 |
| 音響条件が異なり直接利用不能 | 理由を資料へ記録し、承認後にStem専用実装 |
| 通常モード変更が必要 | 対象、影響、戻し方を提示して別途承認を受ける |

アプリ最上位の画面切り替えなど、既存ファイルへの最小接続変更が不可避な場合は、変更対象・変更前・変更後・影響・戻し方を提示してから承認を受ける。

### 3.4 承認済みの通常モードUI境界変更

2026-07-15、Stem Modeを別画面として表示し、モード切り替え後も通常モードの処理状態を保持するため、次の2ファイルだけを変更する方針が承認された。

#### `ContentView.swift`

- 現在の`ContentView()`が持つ既定動作は変えない
- ルート画面が既存の`ProcessingActions`を渡せるinitializerを追加する
- ルート画面から表示する場合だけ、モード切り替えによる`onDisappear`で通常モードの処理状態を破棄しない
- アプリ終了時のshutdownはルート側で実行する
- 通常モードの画面構成、操作、解析、DSP、guard、保存、書き出しは変更しない

#### `VelouraLucentApp.swift`

- `ContentView()`の直接表示を、通常モードとStem Modeを切り替える`VelouraRootView`へ変更する
- 通常モード表示時は既存`ContentView`を使用する
- 音声処理、解析、品質判断へ条件分岐を追加しない

この2026-07-15時点の2ファイル境界は、その後に承認された通常／Stem共通ワークスペース外枠へ置き換えた。現在の承認済みUI境界は、`VelouraLucentApp.swift`、`VelouraCommands.swift`、`ContentView.swift`、`VelouraMainWorkspaceView.swift`、`WorkspaceFooterView.swift`と、新しいRoot／共通外枠／共通toolbar／Stem専用Viewである。

次は現在も承認対象に含まれない。

- 通常モードの解析条件変更
- 通常モードのDSP変更
- 通常モードのguard・品質判定変更
- 通常モードの音質判断とStem固有の音質判断を同じ実装へ混在させる変更
- 承認済み共通UI境界以外の通常モード既存ファイル変更

共通外枠の切り戻しは、Rootが所有する共通`NavigationSplitView`、共通toolbar、共通中央・下部配置を変更前のモード別画面組立てへ戻すUI差分だけを対象とする。通常モードの音声処理、解析、DSP、guard、マスタリング、保存成果物は切り戻し対象に含めない。

## 4. Stem Modeの基本構造

### 4.1 別画面だが別の操作体系にはしない

通常モードとStem Modeは別画面である。

Stem Mode画面は、通常モードの次を基礎として維持する。

- 上部操作
- 左サイドバー
- 中央の基本表示／詳細解析
- 右上の補正／マスタリング／アプリ設定
- 右下の解析結果と品質確認
- 下部の直近ログ／全体工程
- 補正ログ／マスタリングログ
- A/B試聴
- 一時保存
- 書き出し
- エラー表示
- 完了通知

Stem Mode専用の6ページ構成、単一系列ログ、固定14工程、独自の開始ボタンを前提としない。

### 4.2 状態分離

通常モードとStem Modeは別の状態所有者を持つ。

Stem Modeの次の状態を通常モードの`ProcessingJob`へ混ぜない。

- 入力2mix
- raw 4Stem
- 補正済み4Stem
- Stem別設定
- 分離進捗
- Stem別処理進捗
- 再ミックス
- Stem Mode最終版
- Stem固有警告
- Stem用一時ファイル
- Stem用ログ
- Stem用エラー

モードを切り替えても、通常モードの入力・補正後・最終版を勝手に削除しない。

ここでいう状態分離は、通常モードとStem Modeの処理データを混在させないという意味である。

次の仕様を新設する意味ではない。

- ウィンドウIDによるrun管理
- ウィンドウごとのモード契約
- 複数ウィンドウ間で処理状態を共有するか選択する設定
- 通常モードの既存状態所有方法の変更

通常モードの状態所有は現行実装を維持し、Stem Modeに必要な状態だけをStem専用側へ追加する。

## 6. Stem Modeの二段階処理

### 6.1 補正段

補正段は次の工程である。

```text
選択・解析開始済みの入力2mix
→ 分離用44.1 kHz信号の生成と処理判断用評価
→ 4Stem分離
→ 分離結果の基本検証
→ 各raw Stemの解析
→ Stem別ノイズ除去
→ Stem別補正
→ 各工程のguard
→ 補正済み4Stemの一時保存
→ 補正段完了
```

補正段完了後にマスタリングを自動実行しない。

### 6.2 マスタリング段

マスタリング段は、別のユーザー操作で開始する。

```text
保存済み補正4Stem
→ 4Stem読み込み
→ 純粋加算再ミックス
→ 音声として成立するための構造確認
→ 既存マスタリング前解析
→ 既存マスタリングと既存guard
→ Stem Mode最終2mixの一時保存
→ 最終解析
→ 品質確認
→ 書き出し可能状態
```

マスタリング段は簡易版へ置き換えず、既存マスタリング処理を使用する。

### 6.3 書き出し

書き出しはユーザー操作で行う。

主な書き出し対象：

- 補正後再ミックス（補正後2mix）
- 補正済み4Stem一式
- Stem Mode最終2mix

raw Stem、raw再ミックス、No vocalsを必須書き出し対象にしない。

## 7. 入力と分離

### 7.1 入力

- 入力ファイルは変更せず保持する。
- monoは左右同一信号のstereoへ変換する。
- stereoは左右を保持する。
- multichannelは、確認できたchannel layoutとCore Audioの変換情報を使用する。
- unknown layoutやdiscrete channelsを推測変換しない。
- 自動決定できない場合は、使用するチャンネルとstereo変換係数をユーザーへ確認する。

### 7.2 分離設定

初期設定はMeta Demucs標準を基準とする。

```text
model: htdemucs
shifts: 1
overlap: 0.25
split: true
segment: 7.8秒
batchSize: 1
seed: runごとに保存
```

分離器の入力契約は44.1 kHz／stereo／Float32とする。

### 7.3 AI責務境界

AIの役割はDemucsによるvocals／drums／bass／otherの4Stem分離までとする。

分離後の次の処理にAIを使用しない。

- Stem品質評価
- 補正候補生成
- 補正候補比較
- DSP採否
- Stem組み合わせ選択
- 再ミックス選択
- マスタリング入力選択

分離後は、通常モードの解析、route決定、DSP、DSP内部guard、既存マスタリングを基礎とする。

### 7.4 承認済みサンプルレート契約

2026-07-15、次のサンプルレート経路が承認された。

1. 入力音源そのものは変更せず保持する
2. Demucsへ渡す分離用信号を44.1 kHz／stereo／Float32で作成する
3. Demucsが生成したraw 4Stemは44.1 kHzの正本として保持する
4. Stem補正へ渡す直前に、各Stemを1回だけ48 kHzへ変換する
5. Stem解析、通常モードから再利用する下位DSP、処理前後guardは48 kHzで実行する
6. 補正済みStemは48 kHzで一時保存する
7. 補正段で、48 kHzの補正済み4Stemを純粋加算し、48 kHzの補正後再ミックスを検証・保存・表示する
8. 別操作のマスタリング段では、補正段で表示した同一の48 kHz再ミックスを、再生成や追加のサンプルレート変換なしで既存`MasteringService`へ渡す
9. 通常モードの既存DSPまたはguardが処理前信号の維持、既存light経路、スキップを選んだ場合は、その1本の処理経路をそのまま継続する
10. Stem処理自体の非致命的失敗で補正済みStemを生成できない場合だけ、そのraw Stemを1回48 kHzへ変換して補正済みStemセットへ加える

通常モードの実運用経路が48 kHzで解析・補正・マスタリングを行うため、通常モードで検証されている処理条件へ合わせる。

同じStemへ不要な往復変換を行わない。44.1 kHzのraw Stemを48 kHzへ変換した後は、補正、保存、再ミックス、マスタリングを48 kHzのまま進める。

### 7.5 分離直後の確認

- 4Stemが存在する
- vocals／drums／bass／otherが一つずつ存在する
- 各Stemが読み込み可能
- channel数が一致
- sample rateが一致
- frame数が一致
- NaN／Infinityがない
- 破損ファイルでない

残差、ピーク、相関は測定できるが、未校正の数値だけで分離全体を失敗にしない。

## 8. Stem別ノイズ除去・補正

### 8.1 対象Stem

```text
vocals
drums
bass
other
```

### 8.2 補正設定

Stem Modeの補正タブでは、対象Stemを選択する。

各Stemは独立した補正設定を保持する。

- 選択中Stemを明示する
- 選択中Stemのプリセットと補正値を表示する
- 1Stemの変更で他Stemを上書きしない
- 補正開始時に4Stem分の設定を固定する
- 実際に使用した設定を処理結果とレポートへ保持する

### 8.3 処理思想

各Stemは通常モードと同じ一本道で処理する。

```text
raw Stem解析
→ Stem役割とユーザー設定から処理方針を決定
→ 必要なDSPを順番に実行
→ 各DSPに組み込まれた通常モード既存guardで補正量・上限・適用可否を制御
→ 既存guardが弱化、スキップ、処理前信号維持を選んだ場合はその結果を次へ渡す
→ Stem専用の候補生成、候補比較、採用判定を追加しない
→ Stem処理自体の非致命的失敗で補正済みStemを生成できない場合だけ該当raw Stemを使用
→ 1本の補正済みStemを確定
```

16通りの完成候補だけでなく、Stem工程ごとの独自候補、Stem組み合わせ候補、再ミックス回復候補も生成しない。

通常モード既存guardの内部で、一時的な弱化信号を計算して安全上限内へ収める処理は、そのguardの実装として変更せず利用できる。これはStem Modeの成果物候補、品質比較候補、A/B候補として扱わない。

### 8.4 役割別の保護

#### vocals

- 声の芯
- formant
- 倍音
- 息
- 子音
- サ行
- 空気感

息や子音をヒスとして一律除去しない。

#### drums

- attack
- transient
- シンバルの余韻
- 高域の持続音
- 打点
- ダイナミクス

シンバルをヒスやシマーとして一律除去しない。

#### bass

- 基音
- 倍音
- 低域の芯
- 音程感
- 50 Hz／60 Hz付近の音程整合
- 左右位相

基音をハムやrumbleとして一律除去しない。

#### other

- 複数楽器のまとまり
- 残響
- ambience
- 空間
- ステレオ感
- transient
- 高域の広がり

残響や広がりを分離ノイズとして一律除去しない。

役割別情報は、通常モード既存DSPを適用する条件と音楽成分保護の入力として使用する。Stem専用の品質スコア、合否判定器、候補選択器を作る根拠にはしない。

#### 役割別解析と既存routeの接続契約

2026-07-16の実コード調査で、`StemRoleAnalysisService`は各Stemの48 kHz処理信号を解析しているが、`StemCorrectionService`は返された`StemRoleAnalysisSnapshot`を破棄しており、役割別解析値はroute、DSP適用条件、guard、保存、表示へ接続されていないことを確認した。

現在の通常モードrouteは`AnalysisData`と`NoiseMeasurementSnapshot`から先に確定している。Stem Modeでは、次の順序へ修正する。

```text
通常モード共通のAnalysisData・NoiseMeasurementSnapshotから標準routeを作成
→ raw Stemの役割別解析
→ DSP後のStem役割別保護guardで、今回のraw Stem内の音楽成分とDSP差分が重なる区間を確認
→ 通常モードrouteを強めず、必要な工程だけrun／light／skipへ制限
→ 通常モード下位DSPとDSP内部guardを一本道で実行
→ 各DSPの処理前後を、時間位置を保持したStem役割別保護guardで確認
→ 問題があれば該当DSPだけを弱化、skip、処理前信号維持の順で戻す
```

DSP後のStem役割別保護guardは、完成音候補、DSP出力候補、AI品質評価、品質スコアを作らない。処理前後の複数音源を順位付けせず、今回のraw Stemと該当DSPの処理前／処理後だけを基準に、1本の処理結果を安全側へ制限する。

通常モードのactionは全DSPで同じ意味ではない。

- サ行・シマー保護は`light`で既存強度を0.55へ下げる
- シマーピーク制限は`light`で既存反復上限を2回へ下げる
- 低域整理、修復後シマー保護、低中域整理は`light`と`run`が同じ実行になるため、Stem側で同一視しない
- ノイズ除去、高域修復、高域保持、mud増加guardは通常モード下位APIがroute actionを受け取らない
- 低域整理は`HumRemover`と`RumbleReducer`を1工程で実行するため、bassで50 Hz／60 Hzの音程成分だけを保護する場合はStem専用adapterから既存2DSPを分けて適用する

現在の四分位分布と`preserveMinimum`／`preserveStability`だけでは、息、子音、formant、attack、余韻、低域の音程、残響、空間が発生した時間位置をDSP前後で対応付けられない。このため、これらを本番guardへそのまま転用せず、時間位置を保持するStem専用解析へ拡張する。

本番の適用条件と保護量は、別の曲やサンプル音源の測定値から固定しない。毎回、今回の入力2mix、今回のraw Stem、該当DSPの処理前Stem、該当DSPの処理後Stem、今回のraw再ミックス、今回の補正後再ミックスを基準にする。新しい絶対閾値、役割別固定mapping、Stem専用品質スコアを追加しない。

役割別保護は次を正式なStem Mode機能として実装する。

- vocals：有声音、非周期成分、息、子音、サ行、formant相当のスペクトル包絡、倍音列、声の芯
- drums：onset、attack、transient、帯域別のシンバル余韻
- bass：基音、倍音列、音程成分、50 Hz／60 Hz付近の音楽成分、低域位相
- other：残響尾、ambience、mid／side空間成分、ステレオ像

判断が曖昧な時間・帯域は音楽成分を優先し、そのDSPで音を変更しない。これはStem全体を直ちにrawへ戻す意味ではなく、該当DSPの処理前信号を維持する意味である。

#### 所有AI生成音源の検証用途

ユーザーが`Tests/Fixtures/Sample_audio`の次の3曲を所有AI生成音源として指定した。

- `嘆き-2.wav`：304.8秒
- `星屑のシンパシー.wav`：246.2秒
- `violin #002 睡眠.wav`：193.0秒

この3曲は、次の開発検証にだけ使用する。

```text
入力2mixを44.1 kHz／stereo／Float32へ変換
→ 固定Revision HTDemucsで4Stem分離
→ 各raw Stemを48 kHzへ1回だけ変換
→ 通常モード共通解析・NoiseMeasurement
→ 役割別解析
→ 既存route・下位DSP・DSP内部guardによる補正
→ 補正後Stemの一時保存
→ メモリ上のraw再ミックスと一時保存した補正後再ミックスの解析
```

確認するのは次である。

- 通常モード共通解析、NoiseMeasurement、役割別解析の値が有限値で取得できる
- 通常route、各DSP、DSP内部guard、Stem役割別guardが正しい前後音声に接続する
- 同一seed・設定で分離が再現する
- 問題DSPまたは該当Stemだけを安全な状態へ戻せる
- 4Stemの純粋加算、補正後再ミックス、既存マスタリングが成立する

この3曲の値から、本番用の閾値、固定mapping、DSP適用条件、音質合否を作らない。本番では毎回の入力2mix、raw Stem、DSP処理前後Stem、raw再ミックス、補正後再ミックス自身の関係だけを基準にする。

ユーザーへStem単位の専門的A/B判定を求めない。完成音の確認を求める場合だけ、入力2mix、補正後再ミックス、Stem Mode最終版について「自然」「違和感がある」「判断できない」の3段階とする。「判断できない」は品質選択に使用せず、自動処理は安全側として音を変更しない。

### 8.5 ピーク

各Stemへ独立した最終limiterを適用しない。

Stemごとの異なるピーク減衰によって、4Stem間の相対バランスが変わるためである。

各Stemでは次を確認・記録する。

- sample peak
- True Peakを測定できる場合の値
- over-range sample
- NaN／Infinity

最終ピーク制御は、補正済み4Stemを純粋加算した後の既存マスタリングで行う。

## 9. 再ミックス

### 9.1 必須の再ミックス

補正段の最後に、補正済み4Stemを同じ時間軸で純粋加算する。検証・保存・表示した同一の補正後再ミックスを、別操作のマスタリング段へ渡す。

```text
correctedMix
  = correctedVocals
  + correctedDrums
  + correctedBass
  + correctedOther
```

再ミックス段で次を行わない。

- 自動音量変更
- 自動パン
- 自動ステレオ幅変更
- 自動トーン変更
- 自動コンプレッション
- 自動ラウドネス調整
- 最終limiter

### 9.2 raw再ミックス

raw再ミックスは必須保存成果物にしない。

入力2mixで代用できない次の検証が必要な場合だけ、内部の一時データとして生成できる。

- 分離直後4Stemの再合成誤差
- 入力2mixとの差分
- 補正前後の変化を分離して測定する必要がある場合

raw再ミックスについて、次を行わない。

- 必須保存
- 必須書き出し
- 常設UI表示
- マスタリングfallbackの既定候補化
- 1Stemの問題による4Stem全体のraw化

保存成果物として必要になった場合は、用途・代用不能理由・保存しない場合の問題を提示し、別途承認を受ける。

## 10. guard、警告、失敗、fallback

### 10.1 guardの目的

通常モードのguardは、独立した品質確認工程でも、複数の完成候補から最良音源を選ぶ工程でもない。

guardは各DSPの処理経路に組み込まれ、主に次を行う。

- ノイズ除去量や補正量を既存の安全上限へ収める
- 高域修復や音楽成分の戻しすぎを抑える
- 既存routeの`light`条件で処理強度または反復回数を弱める
- 適用不要または改善不要なDSPをスキップする
- 安全な処理結果を作れない場合は、そのDSPの処理前信号を維持する
- NaN／Infinity、異常ピークなど音声として成立しない状態を防ぐ

通常モード既存guardの内部で弱化率や一時信号を複数計算する場合があるが、これは1工程の出力を安全範囲へ収める内部制御である。Stem Modeの独自候補生成、候補比較、AI品質評価、ユーザー選択へ拡張しない。

frame、channel、sample rate、ファイル形式、NaN／Infinityなどの構造確認は、音声を次工程へ渡せるか確認する境界検証であり、音質候補を選ぶguardとは分けて扱う。

位相、相関、残差、分離アーティファクトは解析・表示・レポートに利用できる。ただし、通常モードに存在しない自動棄却、再ミックス候補探索、ユーザー選択の条件へしない。

### 10.2 正常な変化を失敗にしない

ノイズ除去や補正を行えば、次は変化してよい。

- 波形
- 周波数成分
- ピーク
- ラウドネス
- ダイナミクス
- 帯域バランス

単に差が生じたことを失敗条件にしない。

### 10.3 対応分類

各Stemは、通常モードと同じ1本の処理経路で次のように扱う。

1. 解析結果とユーザー設定から既存routeを決定する
2. 今回のraw Stemの時間整列した役割別解析から、音楽成分と処理対象を分離できるか確認する
3. routeが`skip`ならDSPを実行せず、現在信号を次へ渡す
4. routeが`light`なら通常モード既存の弱い経路を実行する
5. routeが`run`なら通常モード既存の通常経路を実行する
6. 既存guardが補正量制限、反復停止、処理前信号維持を行った場合は、その結果を次へ渡す
7. Stem役割別保護guardで、該当DSPの処理前後における音楽成分を確認する
8. 明確な問題がある場合は、該当DSPの処理量を弱める
9. 安全に分離できなければ、該当DSPだけをskipする
10. それでも成立しなければ、そのDSPの処理前Stemを維持する
11. Stem処理全体として補正済みStemを生成できない場合だけ、該当raw Stemを使用する
12. 音声として処理できない場合だけ継続不能な失敗にする

1Stemの問題を理由に、他Stemの成功結果を破棄したり、補正後4Stem全体をrawへ戻したりしない。

再ミックス後にStem・DSP・弱化方法を組み替えて候補を列挙しない。複数候補からユーザーへ採用判断を求めない。

### 10.4 一部Stemの失敗

1Stemの非致命的失敗で、他3Stemと成功済み成果物を破棄しない。

可能な対応：

- 問題のある解析だけを警告
- 通常モード既存routeによるDSPスキップ
- 通常モード既存light経路による弱化
- 通常モード既存guardによる処理前信号維持
- Stem役割別保護guardによる該当DSP差分だけの弱化
- Stem役割別保護guardが判断できない場合の該当DSP処理前Stem維持
- 該当Stemだけrawを使用
- 他Stemの成功結果を保持
- 補正済みStemセットとして処理を継続

Stem専用の候補比較や16通りの再ミックス探索は行わない。処理前後を複数候補として順位付けせず、該当DSPの差分だけを決定的に弱める。各Stemを純粋加算して再検証し、安全な再ミックスを作れない場合だけ、確定済み成果物を保持して停止する。

### 10.5 致命的エラー

次のように本当に処理を継続できない場合だけ停止する。

- 入力ファイルを読めない
- 分離そのものが成立しない
- 必要なraw Stemが存在しない
- raw Stemが音声として読み込めない
- 必要な4Stemの時間軸を揃えられない
- 再ミックス用の必須音声を生成できない
- 最終音声を書き出せない

マスタリング失敗時も、補正済み4Stemを保持する。

## 11. Stem Mode画面

### 11.0 共通ワークスペース外枠

Stem Modeは別画面であるが、別の画面構成を持たない。`VelouraRootView`が通常モードと同じ`WorkspaceShellView`、`WorkspaceToolbarView`、左右開閉状態、ウィンドウ背景、最小サイズ、フルスクリーン状態を継続して所有する。

モード切り替えで交換するのは次の内容だけである。

- 左：`VelouraSidebarView`／`StemModeSidebarView`
- 中央：`ContentView`／`StemModeWorkspaceView`
- 右：`VelouraInspectorView`／`StemModeInspectorView`

中央は両モードとも、固定ヘッダー、基本表示／詳細解析の切り替え、スクロールする本文、固定下部、詳細ログ切り替えを`WorkspaceCenterLayout`で組み立てる。下部の直近ログと全体進捗は`WorkspaceFooterLayout`で同じ寸法と配置を使い、表示内容だけを各モードから渡す。

左右のタイトルバー開閉ボタンは、同じ`LiquidGlassMotion.panel`とモーション低減設定を使用する。左サイドだけ状態を即時変更せず、右インスペクタと同じ0.24秒の`easeInOut`で開閉する。

Stem Mode側で別の`NavigationSplitView`、別のwindow configurator、別のtoolbar、別の左右幅管理を作らない。

### 11.1 上部

通常モードと同じ位置と役割を維持する。

- 音声を選ぶ
- 補正を実行／キャンセル
- マスタリングを実行／キャンセル
- 書き出し

Stem固有差分：

- 補正ボタンで分離から補正済み4Stem保存までを実行
- マスタリングボタンで再ミックスから最終版生成までを実行
- 1つのStem開始ボタンで全工程を自動実行しない

### 11.2 左サイドバー

通常モードの「音源」と「工程」を維持する。

音源：

- 入力2mix
- raw vocals／drums／bass／other
- 補正済みvocals／drums／bass／other
- rawを使用したStemの表示
- 補正後再ミックス
- Stem Mode最終版

工程：

通常モードと同じく、上から「補正」と「マスタリング」の2つの処理ブロックを縦に置く。Stem専用の第3ブロックや、書き出しブロックを左サイドバーへ追加しない。

各ブロックでは、通常モードと同じ次の表示階層を維持する。

- 状態アイコンと処理名
- 経過時間
- 現在実行中の工程名、または処理全体の状態
- 実行中工程の詳細
- 進捗バーと進捗率
- 全内部工程の縦一覧
- 待機、実行中、完了、省略、失敗の状態表現

補正ブロックの内部工程へ、通常モードの補正工程に加えて次を組み込む。

- 入力2mixの処理用解析
- 4Stem分離
- Stem別解析
- Stem別ノイズ除去・補正
- 補正済み4Stem保存

マスタリングブロックの内部工程へ、通常モードのマスタリング工程に加えて次を組み込む。

- 補正済み4Stem読込
- 純粋加算による再ミックス
- 再ミックス解析
- 既存マスタリング
- 最終解析とStem Mode最終版保存

追加工程は、それぞれ該当するブロックの全工程一覧へ表示し、現在工程、詳細、進捗率と実際の進捗イベントを一致させる。

モデル取得、モデル検証、モデル修復を音楽処理の工程一覧へ含めない。

書き出しは通常モードと同じく上部のユーザー操作と下部の全体進捗で扱い、左サイドバーへ独立した処理ブロックとして追加しない。

### 11.3 中央の基本表示

通常モードと同じ基本表示を維持する。
上部の`基本表示 / 詳細解析`タブで選択中の画面が分かるため、タブ直下へ「基本表示」の見出しや説明文を重複表示せず、波形と試聴比較から表示を始める。

- 波形
- A/B試聴
- 同じ再生位置
- ラウドネス合わせ
- 再生中スペクトル
- ベクトルスコープ
- ラウドネスメーター
- スペクトログラム

A/Bは、通常モードと同じく、すべての処理が終わった後にユーザーが実音を聴き比べる試聴機能とする。

A/B対象：

- 入力：入力2mix
- 補正後：補正済み4Stemの純粋加算2mix
- 最終版：既存マスタリング後のStem Mode最終2mix

A/Bの選択、再生、ラウドネス合わせ、ユーザーの試聴結果を、DSP採否、Stem選択、再ミックス入力、マスタリング入力の自動決定に使用しない。

上記の2mix試聴欄へraw Stem、補正済みStem、内部診断成果物を混在させない。

基本表示には、2mix試聴欄とは独立したStem試聴欄を追加する。ドラム、ベース、その他、ボーカルから1役割を選び、検証済みraw Stemと検証済み補正後Stemの波形を上下2段で表示する。Stem試聴欄は、raw再生、補正後再生、再生・一時停止、停止、raw／補正後切替、同一時間へのシーク、専用音量、再生時だけのラウドネス合わせを独立して所有する。2mix試聴欄とStem試聴欄のA/B選択、再生位置、音量、ラウドネス合わせは共有しない。一方の再生を始めた時は他方だけを停止する。

中央のStem選択と右のStem別補正設定は、同じ4役割を同じ順番と表示形式で示すが、選択状態は共有しない。中央の選択は表示・試聴対象だけを切り替え、右の選択は補正設定の表示・編集対象だけを切り替える。どちらの役割選択も補正値の変更、DSP採否、品質判定を実行しない。

補正前はraw Stemだけを表示・再生し、補正後Stem側を無効表示する。補正後Stemは保存・検証済みになった役割だけ表示・再生する。入力変更または補正キャンセルで一時成果物が削除された場合は、対応するStem波形と再生対象も消去する。

- ラウドネス推移
- ダイナミクス
- 全曲平均スペクトル
- 帯域詳細
- 処理前後差分

Stem固有差分：

- 相関
- 残差
- 分離アーティファクト

`Stem固有解析`と`再ミックス固有解析`は、通常モードの詳細解析内にある同じ`analysisCard()`と`DisclosureToggleButton`を直接使用し、専用の複製カード装飾を持たない。同じ全幅ガラス背景、丸い開閉ボタン、見出し、`?`ヘルプを使用し、初期状態は閉じる。開いた内容は固定の小さい文字を使わず、macOSの文字サイズへ追従する`callout`以上で表示する。

Stem Modeの結果表示と処理ログでは、現在の実行モードを誤認させないため、再利用元を「通常モード」と表示しない。Stem Mode内で使用する共通資産は「共通の補正判定」「既存DSP」「既存の補正後高域保持」のように、その処理の役割を表示する。設計資料では、通常モードで実績のある資産を再利用している事実を引き続き明記する。

## 12. 一時保存とキャンセル

### 12.1 一時保存

補正段の完了時に、補正済み4Stemを一時保存する。

マスタリング段の完了時に、Stem Mode最終2mixを一時保存する。

Stem Modeの作業状態は通常モードと同じくアプリ起動中のメモリで管理する。run、checkpoint、schema、設定・解析結果のJSON保存、アプリ再起動後の作業再開、保存履歴は持たない。

Stem Modeで必要な音声だけを`FileManager.default.temporaryDirectory`配下のStem専用一時ディレクトリへ保存する。

- Demucs入力用2mix
- 分離直後のraw vocals／drums／bass／other
- 補正済みvocals／drums／bass／other
- 補正後再ミックス
- Stem Mode最終2mix

raw再ミックスは、入力2mixで代用できない再合成診断と補正前後比較の間だけメモリ上で生成する。保存成果物、書き出し対象、A/B対象、マスタリング入力にはしない。

補正段は、分離、分離Stem検証、Stem解析、Stem補正、補正済みStem検証、純粋加算、補正後再ミックス検証・保存・表示を一本道で完了する。読み込み可能な検証済み補正Stemが4役割すべて揃い、補正後再ミックスも検証・保存できた時だけ完了とする。表示進捗は処理可否を決める入力ではなく、実処理の成功時に補正工程100%へ確定する。その後は`readyForMastering`で停止し、ユーザーの「マスタリングを実行」操作を待つ。

### 12.2 中断

通常モードと同様に、キャンセル操作は確認用3択を表示せず、実行中の処理を直接キャンセルする。

#### 補正キャンセル

- 実行中Taskをキャンセルする
- その補正処理で生成したraw Stem、補正済みStemなどのStem一時音声を削除する
- 補正工程と表示結果を未実行状態へ戻す
- 選択中の入力音源、入力解析の状態と結果、入力波形、入力再生対象、補正・マスタリング設定は維持する
- モデル資産と通常モード一時ファイルには触れない

#### マスタリングキャンセル

- 実行中Taskをキャンセルする
- 既存マスタリングが生成中の一時音声、最終2mixなど、マスタリング段で生成した未完成ファイルだけを削除する
- 補正済み4Stem、補正後再ミックス、その波形・スペクトログラム・解析値・試聴、補正工程100%を維持する
- `readyForMastering`へ戻し、ユーザーがマスタリングを再実行できる状態にする

### 12.3 入力変更とアプリ終了

- 補正完了後を含め、処理Taskが動いていない時は入力を変更できる
- 入力変更が確定した時は、変更前の入力解析Taskをキャンセルし、入力解析結果、入力波形、入力再生対象、Stem一時音声を削除してから新しい入力へ切り替える
- 変更前入力の非同期解析が後から完了しても、変更後入力の状態を上書きさせない
- アプリ終了時は現在セッションのStem一時音声を削除する
- アプリ起動時の旧作業検索、保存一覧、読込、再開、schema移行、互換shimは追加しない

### 12.4 一時音声の安全な書込み

各音声はStem専用一時ディレクトリ内の一時名へ書き込み、sample rate、channel、frame数、有限値、読込み可否の検証に成功した後で正式な一時ファイル名へ変更する。

SHA-256、byte count、manifest、ディレクトリ全体のcommitは、モデル資産の検証には使用しても、作業用音声の状態管理には使用しない。

分離中に4Stemの一部を生成できない場合、その分離試行で作成中だった不完全なraw Stemだけを削除する。入力2mix、入力解析結果、設定は維持する。

Stem補正では、1Stemまたは1DSPの問題で成功済みの他Stemを削除しない。問題DSPの弱化、skip、処理前Stem維持、必要な場合だけ該当raw Stemへの復帰を行う。マスタリングでは、失敗またはキャンセルしても補正済み4Stemを維持する。

## 13. 音質評価

### 13.1 通常モードの資産を優先する

再利用を優先する。

- `AudioAnalyzer`
- `NoiseMeasurementService`
- `AudioComparisonService`
- `MasteringAnalysisService`
- 通常モードの下位DSP
- 処理前後guard
- 異常値検出
- 品質評価
- `MasteringService`

### 13.3 再ミックス後

補正後再ミックスは、通常モードと同じ既存マスタリング前解析へ渡す。

追加で測定・表示できるStem固有項目：

- 再合成誤差
- 残差
- stem間の漏れ
- 位相
- 相関
- 分離アーティファクト

これらは解析、Stem固有guard、表示、レポート、実音確認の材料とする。数値が変化しただけで劣化と断定せず、再ミックス候補を生成・選択しない。

再合成誤差は、入力2mixとraw 4Stemの純粋加算が一致するかを確認する。stem間の漏れは、正解isolated Stemが存在しないため絶対的な漏れ量とは断定せず、補正前後でStem間の共通成分が増加したかを相対確認する。位相・相関・ステレオ像は単独の数値で判定せず、今回のraw再ミックスと補正後再ミックスの同じ時間・帯域を比較する。

明確なNaN／Infinity、clip、異常peak、位相反転、ステレオ像の破損、再合成不能を検出した場合は、保存したDSP単位の処理履歴から原因Stemと原因DSPを特定し、弱化、skip、処理前Stem維持、必要時だけ該当raw Stemの順で戻して再ミックスを再検証する。原因を特定できない曖昧な変化は自動音質判定に使わず、音を変更しない。

再ミックス境界では、sample rate、channel、frame、NaN／Infinity、ファイル読込など、既存マスタリングへ入力できる音声かを確認する。位相、相関、残差、分離アーティファクトを理由にStem・DSP・弱化方法を組み替えた候補探索を行わない。

安全性を確認した補正後再ミックスは、その1本を既存マスタリングへ渡す。通常モードに存在しない完成候補比較、品質スコア、AI品質選択、ユーザーによる専門的Stem判定は追加しない。

### 13.4 最終版

Stem Mode最終版は、既存マスタリング後に通常モードと同じ最終解析・品質確認を行う。

通常モード最終版は必須比較対象にしない。

通常モードとの完成音比較を行う場合は任意機能として別に扱う。

### 14.5 補正段とマスタリング段の二段階実行境界

補正段とマスタリング段は次の実行境界へ分離する。

- `StemWorkflowService.processCorrection`は、入力準備、4Stem分離、Stem解析・補正、補正済み4Stemの一時保存、純粋加算、補正後再ミックスの検証・一時保存までを順番に実行する。検証済み補正Stemが4役割すべて揃い、補正後再ミックスも検証・保存できた時だけ補正完了とし、その成功結果から表示進捗を100%へ確定する
- 補正段は補正後再ミックスを波形、スペクトログラム、解析値、試聴へ接続した後、マスタリングを呼ばず`StemWorkflowSession.readyForMastering`で停止する
- `StemWorkflowService.processMastering`は、ユーザーが別の「マスタリングを実行」操作を行った時だけ、補正段で表示した同一の補正後再ミックスと実行時点の`MasteringSettings`を受け取って開始する。4Stemの再加算や重複WAV生成は行わない
- `StemModeWorkspaceModel`は、補正処理が成功して`readyForMastering`になり、検証済み補正Stemが4役割すべて揃うまでマスタリング操作を無効にする。表示進捗値だけを開始条件にしない
- 待機中は補正設定を固定し、マスタリング設定だけを変更可能にする
- 実行時点のマスタリング設定はメモリ上のセッションへ渡し、設定JSONやidentityを作らない
- マスタリング段で失敗またはキャンセルした場合、sessionは補正段の完了状態、補正済み4Stem、補正後再ミックスとその表示を保持し、最終版だけを無効化する
- 単一の「Stem Modeを開始」操作は実行経路から除去し、「補正を実行」と「マスタリングを実行」を分けた

現行のメモリ状態とStem一時音声に対し、検証済み補正Stemが4役割すべて揃い補正後再ミックスが検証・保存される前のマスタリング禁止、成功結果による補正表示100%確定、補正直後の表示接続、二段階操作、マスタリング失敗時の補正表示保持、補正後再ミックスの既存マスタリング直接接続をテストで確認済みである。

### 14.6 44.1 kHz raw保持とStem別48 kHz補正経路

2026-07-15、連続補正段を次の処理契約へ更新した。

- 分離直後のraw vocals／drums／bass／otherは44.1 kHzのまま保存する
- 各raw Stemを補正開始境界で1回だけ、`AVAudioConverter`のmastering品質アルゴリズムにより48 kHzへ変換する
- `StemRoleAnalysisService`と通常モードの下位DSPを呼ぶ`StemCorrectionService`へ同じ48 kHz処理信号を渡す。時間整列した役割別解析をDSP後の役割別保護guardへ接続し、通常モードrouteを強めず、DSP差分の弱化または当該DSPのスキップだけを行う
- 補正済みStemは48 kHzだけを受理する
- vocals／drums／bass／otherは、それぞれ独立した補正プリセットと12設定値を持つ。設定はrole選択UI、現在セッション、該当roleのcorrectorまで混同せず受け渡す
- 各Stemは通常モード共通のraw解析から標準routeを決め、9つの下位DSPを`run`／`light`／`skip`で順番に実行する。各DSPとDSP内部guardが返した1本をStem役割別保護guardへ渡し、該当DSPの弱化、skip、処理前信号維持を行う接続は実装済みである
- 各DSPでは、Stem役割別保護guardによる弱化、skip、処理前Stem維持を先に行う。1Stemのcorrector自体が非致命的エラーとなり補正済みStemを生成できない場合だけ、そのStemを48 kHz raw fallbackとする
- 現行`StemWorkflowService`は補正済み4Stemを1回だけ純粋加算し、構造的に継続可能な補正後再ミックスだけを既存マスタリングへ渡す
- 位相・相関・残差・帯域・noise・peakは保存・表示・reportに加え、明確な破損時の原因DSP特定と段階的復帰へ使用する。数値変化だけによる候補選択や自動棄却には使わない

- 16通りの完成組み合わせ、工程別のStem専用候補、再ミックス回復候補を生成しない

現行コードで、成功済みStem保持、48 kHz純粋加算、補正後再ミックスの既存マスタリング直接接続を重点テストで確認済みである。

## 17. 実装中の承認境界

次の場合は作業を停止し、ユーザーへ確認する。

- 承認済み共通UI境界以外の通常モード既存ファイル変更が必要
- 通常モードの解析・DSP・guard・品質評価の変更が必要
- Stem分離後にAIによる品質評価・候補選択が必要
- Stem専用の候補生成・候補比較・自動選択が必要
- 承認済みの2mix試聴欄と独立Stem試聴欄以外の比較対象または操作が必要
- ウィンドウ単位の処理状態仕様が必要
- Stem専用の新しい絶対閾値、固定mapping、品質スコア、別音源の測定値を本番基準へ追加する必要がある
- 自動判定できない入力channel layoutがある
- raw再ミックスの恒久保存が必要
- 新しい書き出し成果物が必要
- 既存マスタリングでは要求を満たせない
- 現在承認されていないfallbackが必要
- 音質、操作、保存、書き出しへ影響する仕様変更が必要
- モデルRevisionまたは依存versionの変更が必要
- 追加ダウンロードや外部通信が必要

停止時は、対象、根拠、選択肢、音質・動作への影響を提示する。
