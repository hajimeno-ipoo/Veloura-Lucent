# 目的

Veloura Lucentへ、通常モードとは別画面で使用する本番用Stem Modeを実装する。

処理経路は次のとおりとする。

```text
入力2mix
→ 4Stem分離
→ Stem別ノイズ除去
→ Stem別補正
→ 補正済み4Stem保存
→ 補正済み4Stemの純粋加算・検証
→ 補正後再ミックス2mix保存・表示
→ 別のユーザー操作
→ 既存マスタリング
→ Stem Mode最終2mix保存
→ ユーザー操作による書き出し
```

Stem Modeは通常モードと別画面だが、別のアプリや別の操作体系にはしない。

通常モードの画面構成、操作方法、補正段とマスタリング段の二段階処理、試聴、解析、設定、進捗、ログ、一時保存、品質確認、書き出しを基礎とし、Stem Modeに必要な差分だけを追加する。

通常モードの音質・処理結果・画面動作を変えず、音楽成分保護、再現性、汎用性、実用速度を確保し、通常モードと同等以上を目標とする音質を実現する。

# 方針

## 通常モードの保護

- 通常モードの解析条件、ノイズ判定、補正量決定、DSP順序、guard、許容範囲、fallback、マスタリング、ラウドネス、ダイナミクス、ピーク制御、品質評価を変更しない。
- 通常モードの音声I/O、サンプルレート変換、表示値と処理値の接続を変更しない。
- 通常モード側へStem用の音質条件分岐を追加しない。
- 通常モード既存ファイルの変更は、承認済み共通UI境界の`VelouraLucentApp.swift`、`VelouraCommands.swift`、`ContentView.swift`、`VelouraMainWorkspaceView.swift`、`WorkspaceFooterView.swift`に限定し、解析、DSP、guard、マスタリング、品質判断を変更しない。
- 承認済み共通UI境界以外の通常モード既存ファイル変更が必要になった場合は、実装前に停止し、対象、理由、影響、戻し方を提示して承認を求める。
- 現在保持しているStemコードを一から削除せず、適合するモデル管理、分離、変換、一時保存、二段階workflow、純粋加算、既存マスタリング接続、UI、テスト基盤を選別して再利用する。
- サブエージェントは使用しない。

## AIの責務

AIの役割は、Demucsによる次の4Stem分離までに限定する。

- vocals
- drums
- bass
- other

AIへ次を行わせない。

- Stem品質評価
- 補正候補生成
- 補正候補比較
- DSP採否
- Stem組み合わせ選択
- 再ミックス選択
- マスタリング入力選択

分離後は、通常モードで実績のある解析、route決定、DSP、DSP内部guard、品質評価、既存マスタリングを基礎とする。

## モデル管理

- モデルの有無、破損、Revision、容量、SHA-256、取得、修復、完全再取得、再検証は、右サイド「アプリ」タブの「Stem分離」で扱う。
- モデル状態にかかわらずStem Mode画面を維持し、入力選択と入力表示解析は利用できる。補正だけをモデル利用可能まで無効にする。
- モデル名、固定Revision、`shifts / overlap`、`split / segment`、`batch size / run seed`は`!`アイコンのポップアップで表示する。
- 初回取得、修復、完全再取得は、通信前に取得元、ファイル名、合計容量、固定Revision、License、通信発生を表示し、ユーザー確認後に開始する。
- 音楽処理中にモデル存在確認、破損確認、SHA-256再検証、取得、再取得、修復、取得待機を行わない。
- 音楽処理はモデル管理で使用可能と確認済みのinstallationを受け取る。
- 確認済みモデルを開けない場合は、成功済み成果物を保持し、自動取得せず右サイド「Stem分離」のモデル状態へ案内する。
- AIモデルは固定Revision、固定容量、固定SHA-256で検証する。
- `mlx.metallib`はアプリへ同梱し、AIモデルのダウンロード処理から分離する。

## 入力・分離・サンプルレート

- 入力ファイルそのものは変更せず保持する。
- 入力選択またはドラッグ＆ドロップが確定した時点で、補正操作を待たずに表示・試聴用の入力解析を開始する。
- 入力2mixの波形、再生、スペクトログラム、主要測定値は、選択した入力ファイルの解析結果へ接続する。
- 入力選択時解析と補正workflow内の分離用44.1 kHz信号生成・処理判断用評価を分離する。
- 入力選択時解析の実行中でも通常モードと同様に補正を開始できる。
- 補正開始と補正キャンセルでは、選択中の入力、入力解析の状態と結果、波形、再生対象を消去しない。
- 入力変更時だけ旧入力解析をキャンセル・消去し、遅れて完了した旧入力の解析結果で新入力を上書きしない。
- monoは左右同一信号のstereoへ変換する。
- stereoは左右を保持する。
- multichannelは確認できたchannel layoutとCore Audioの変換情報を使用する。
- unknown layoutやdiscrete channelsを推測変換しない。自動決定できない場合は停止し、ユーザー判断を求める。
- 分離設定は`htdemucs`、`shifts=1`、`overlap=0.25`、`split=true`、`segment=7.8秒`、`batchSize=1`とする。
- seedは補正開始時に現在セッションへ固定し、アプリ起動中のメモリで保持する。
- Demucs入力は44.1 kHz／stereo／Float32とする。
- raw 4Stemは44.1 kHzの正本として保持する。
- 各Stemを補正直前に1回だけ48 kHzへ変換する。
- Stem解析、下位DSP、guard、補正済みStem保存、純粋加算、既存マスタリングは48 kHzで行う。
- 不要な往復変換を行わない。

## Stem別補正

- vocals／drums／bass／otherは独立した補正プリセットと設定値を保持する。
- 1Stemの設定変更で他Stemを上書きしない。
- 補正開始時に4Stem分の設定を固定し、実際に使用した設定を保存・レポートへ残す。
- 各Stemは通常モードと同じ一本道で処理する。

```text
raw Stem解析
→ 通常モード共通のAnalysisData・NoiseMeasurementから標準routeを決定
→ 今回のraw Stemを時間整列して役割別解析
→ DSP後のStem役割別保護guardで、音楽成分とDSP差分が重なる区間だけを弱化し、安全に分離できない当該DSPをskip
→ 必要なDSPを順番に実行
→ DSP内部の既存guardで安全範囲へ制御
→ DSP処理前後をStem役割別保護guardで確認
→ 問題DSPだけを弱化、skip、処理前信号維持の順で戻す
→ 1本の補正済みStemを確定
```

- 既存routeの`run`、`light`、`skip`を使用する。
- 既存guardによる補正量制限、反復停止、スキップ、処理前信号維持をそのまま継続する。
- Stem専用の候補生成、候補比較、採用判定を追加しない。
- 通常モードguard内部の一時的な弱化信号は、DSP内部制御として扱い、Stem Modeの成果物候補やA/B候補へ拡張しない。
- Stemの役割情報は、既存DSPの適用条件とDSP単位の音楽成分保護に使用する。
- 本番判断は、今回の入力2mix、raw Stem、各DSPの処理前後、raw再ミックス、補正後再ミックスだけを基準にする。サンプル3曲や別音源の値を本番用閾値、固定mapping、DSP適用条件、品質合否へ使用しない。
- DSP後のStem役割別保護guardは、Stem専用候補生成、完成候補比較、品質スコア、AI品質評価を行わない。
- 判断できない時間・帯域では該当DSPの処理前信号を維持する。
- 通常モード既存ファイルを変更せずStem専用adapterへ接続する。既存APIだけでは成立しない場合は実装せず承認境界へ戻る。
- 各Stemへ独立した最終limiterを追加しない。
- 最終ピーク制御は純粋加算後の既存マスタリングで行う。

## guard・失敗・fallback

- guardを独立した品質選択工程にしない。
- 複数候補から最良音源を選ぶ処理にしない。
- 位相、相関、残差、分離アーティファクトを、通常モードに存在しない自動棄却、候補探索、ユーザー選択へ使用しない。
- 位相、相関、残差、Stem間共通成分増加は、今回のraw再ミックスと補正後再ミックスを基準に、明確な破損時の原因Stem・DSP特定へ使用する。
- 問題時は、該当DSPの弱化、skip、処理前Stem維持、必要時だけ該当raw Stem、再ミックス再検証の順で戻す。
- frame、channel、sample rate、ファイル形式、NaN／Infinityなどは、次工程へ渡せる音声かを確認する構造検証として扱う。
- 補正により波形、周波数成分、ピーク、ラウドネス、ダイナミクス、帯域バランスが変わっただけでは失敗にしない。
- 1Stemの非致命的失敗で他Stemや成功済み成果物を破棄しない。
- 既存routeとguardで処理できず、Stem処理自体の非致命的失敗により補正済みStemを生成できない場合だけ、該当raw Stemを1回48 kHzへ変換して使用する。
- 1Stemの問題で4Stem全体をrawへ戻さない。
- 再ミックス後にStem、DSP、弱化方法を組み替えた回復候補を列挙しない。
- 複数候補からユーザーへ採用判断を求めない。
- 入力不能、分離不能、必須Stem欠落、音声読込不能、時間軸不一致、必須再ミックス生成不能、最終書き出し不能など、本当に継続できない場合だけ停止する。
- マスタリング失敗時も補正済み4Stemと補正後再ミックスを保持する。

## 再ミックスとマスタリング

- 補正済みvocals／drums／bass／otherを同じ時間軸で純粋加算する。
- 再ミックス段で自動音量、自動パン、自動ステレオ幅、自動トーン、自動コンプレッション、自動ラウドネス、最終limiterを追加しない。
- raw再ミックスは必須成果物、必須書き出し、常設UI、既定fallbackにしない。
- raw再ミックスは入力2mixで代用できない内部診断が必要な場合だけ一時データとして生成する。
- 補正段で構造的に処理可能と確認した補正後再ミックスを保存・表示し、その同一ファイルだけを既存`MasteringService`へ渡す。
- 簡易マスタリングへ置き換えない。
- 既存のマスタリング前解析、マスタリング処理、guard、最終解析、品質確認を維持する。

## 二段階処理

補正操作は次までを行い、そこで停止する。

```text
選択・解析開始済みの入力2mix
→ 分離用44.1 kHz信号の生成と処理判断用評価
→ 4Stem分離
→ Stem別解析
→ Stem別ノイズ除去・補正
→ 補正済み4Stem保存
→ 純粋加算
→ 再ミックス解析・検証
→ 補正後再ミックス保存・表示
```

別のマスタリング操作で次を開始する。

```text
保存・検証済み補正後再ミックス読込
→ 既存マスタリング
→ Stem Mode最終2mix保存
→ 最終解析
→ 書き出し可能状態
```

補正後にマスタリングを自動開始しない。

## 画面

- 通常モードとStem Modeは別画面で切り替える。
- 通常モードの状態所有方法を変更しない。
- Stem Modeは独立した状態所有者を持つ。
- ウィンドウIDによるrun管理やウィンドウ単位の処理状態仕様を追加しない。
- 通常モードの上部、左サイド、中央、右上、右下、下部の配置と役割を基礎にする。
- 6ページ構成、固定14工程、単一系列ログ、独自の開始ボタンへ戻さない。
- 上部には入力、補正、マスタリング、書き出しを配置する。
- メニューバーはRootが所有する現在モードの操作へ接続し、音声選択、補正／キャンセル、マスタリング／キャンセル、2mix再生、書き出しを通常／Stemで切り替える。
- 表示メニューの「モード」から通常補正／Stem Modeを選ぶと、既存`VelouraAppRuntime.selectMode(_:)`を通してアプリ本体を切り替える。
- Stem個別raw／補正後試聴は独立操作のままとし、メニューバーの2mix再生操作へ混在させない。
- 左サイドバーは「音源」と「工程」の2区画にする。
- 工程区画には「補正」と「マスタリング」の2ブロックだけを縦に配置する。
- 各ブロック内に状態、経過時間、現在工程、詳細、進捗率、全内部工程を表示する。
- Stem固有工程は補正またはマスタリングの該当ブロック内へ追加する。
- 待機、実行中、完了、省略、失敗を通常モードと同じ表現にする。
- 書き出しを左サイドバーの独立ブロックにしない。
- 下部は直近ログと「入力解析、補正、マスタリング、書き出し」の4段階全体進捗を維持する。
- 入力解析は入力選択直後に独立して開始し、補正段の内部工程へ移動しない。
- 中央は入力2mix、補正後再ミックス、Stem Mode最終版の波形、再生、A/B、ラウドネス合わせ、スペクトル、ベクトルスコープ、ラウドネスメーター、スペクトログラム、詳細解析を扱う。基本表示にはこれと独立して、選択中役割の検証済みraw／補正後Stemを上下2段の波形と専用試聴操作で比較する欄を追加する。
- A/Bは全処理完了後にユーザーが実音を聴く機能に限定する。
- A/B操作をDSP採否、Stem選択、再ミックス入力、マスタリング入力へ使用しない。
- raw Stem、補正済みStem、内部診断成果物を2mix試聴欄へ混在させない。独立したStem試聴欄は品質候補選択ではなく、選択中役割のraw／補正後をユーザーが手動で聴き比べるためだけに使用する。
- 右上は解析結果一覧にせず、Stem別補正設定、既存マスタリング設定、アプリ設定を扱う。
- 右下は選択音源のIntegrated Loudness、True Peak、ダイナミクス、ステレオ幅、品質警告、重要警告、完了後レポートを扱う。
- 完了後レポートは通常モードと同じポップオーバーで表示する。
- 詳細ログは補正段とマスタリング段を分ける。

## 一時保存とキャンセル

- 補正段完了時に補正済み4Stemと補正後再ミックスを保存する。
- マスタリング段完了時にStem Mode最終2mixを保存する。
- 補正・マスタリングのキャンセルは確認3択を表示せず、通常モードと同じ直接操作とする。
- 補正キャンセルでは、その補正処理で生成したStem一時音声を削除し、入力音源、入力解析状態・結果、入力波形、入力再生対象、設定を維持して補正工程を未実行へ戻す。
- マスタリングキャンセルでは最終版の未確定成果物だけを削除し、補正済み4Stem、補正後再ミックス、実処理成功から確定した補正工程100%表示を維持して`readyForMastering`へ戻す。
- Stem補正中は成功済みStemをメモリ状態と一時音声で保持し、後続Stemが失敗しても破棄しない。
- run、checkpoint、schema、設定・解析結果のJSON保存、保存履歴、アプリ再起動後の作業再開を持たない。
- 各WAVは一時名へ書き込み、音声検証後に確定する。失敗時は、その処理で作成中だった未完成ファイルだけを削除する。
- 入力変更時とアプリ終了時に、現在セッションのStem一時音声を削除する。
- 起動時の旧作業検索、保存一覧、読込、再開、schema移行、互換shimを追加しない。
- raw再ミックスは内部診断の間だけメモリ上で生成し、保存しない。
- 補正段で表示した補正後再ミックスを重複するmastering入力ファイルへ再保存せず、既存`MasteringService`へ直接渡す。

# 計画

1. 現在のStem専用ファイルを、用途、呼び出し元、処理経路、変更理由、代替処理、影響範囲に基づいて再分類する。
   - そのまま再利用する
   - 通常モードの一本道へ修正する
   - 候補選択専用であるため処理経路から除去する
   - 表示・解析・レポート用途だけに限定する
   - ユーザー承認が必要な変更として停止する
2. `StemCorrectionService`に混在する工程別候補評価と`StemAudioSelectionDecision`を処理経路から除去する。
3. Stem補正を、既存routeの`run`／`light`／`skip`、通常モードの下位DSP、DSP内部guard、処理前信号維持だけで1本の出力を確定する一本道へ修正する。
4. `StemRemixSelectionGuardService`と`recoverCorrectedRemix`による候補比較・候補列挙を処理経路から除去する。
5. 位相、相関、残差、分離アーティファクトを解析、表示、レポートへ使用し、明確な破損時だけ原因Stem・DSPの特定と段階的復帰へ接続する。数値変化だけの自動棄却や候補比較には使わない。
6. 既存のモデル管理分離、二段階workflow、44.1 kHz raw保持、48 kHz補正、Stem別設定、純粋加算、既存マスタリング接続を維持する。run／checkpoint／schema／snapshot永続化は除去する。
7. Rootが所有する1つの共通ワークスペース外枠により、通常モードとStem Modeの左・中央・右の内容だけを切り替える。左右幅、toolbar、中央構造、左右開閉状態、window設定は切り替えない。
8. 通常モードを基礎としたStem Mode画面を実装する。
   - 上部操作
   - 左サイドバー
   - 中央基本表示
   - 中央詳細解析
   - 右上設定
   - 右下音声確認
   - 下部直近ログ
   - 下部全体進捗
   - 補正／マスタリング別詳細ログ

# 目標

- 通常モードとStem Modeが別画面で切り替わる。
- モード切り替え後も通常モードの入力、補正後、最終版、処理状態が保持される。
- 通常モードとStem Modeの状態、ファイル、設定、ログが混在しない。
- Stem Modeが通常モードと同じ画面構成、操作、二段階処理、試聴、設定、進捗、保存、書き出しを基礎とする。
- 入力選択直後に入力解析、波形生成、試聴準備を開始し、補正開始・キャンセル後も入力表示を維持する。
- モデル管理と音楽処理が完全に分離される。
- AI処理が4Stem分離で終了する。
- Stem分離後にAI品質評価や候補選択を行わない。
- Stem専用の候補生成、候補比較、品質選択が処理経路に存在しない。
- 各Stemが通常モードの一本道とDSP内部guardを基礎に処理される。
- Stem役割情報が適用条件と音楽成分保護だけに使用される。
- 1Stemの非致命的失敗で他Stemや成功済み成果物を失わない。
- 補正段が補正済み4Stemを純粋加算し、補正後再ミックスを保存・検証・表示して停止する。
- 別操作のマスタリング段が、その同一の補正後再ミックスを使って既存マスタリングを実行する。
- 補正後再ミックス、補正済み4Stem、Stem Mode最終2mixを書き出しできる。
- A/Bがユーザーの試聴だけに使用される。
- 通常モードの音質と画面動作を変更しない。
- 複数の所有AI生成音源で音楽成分保護、再現性、汎用性、実用速度を確認する。
- 通常モードと同等以上を目標とした音質を確認する。

# 手順

1. 各論理工程の開始前に、対象ファイル、状態所有元、呼び出し元、出力先、関連テストを確認する。
2. 最初にStem専用コードをファイル単位で再分類し、処理経路を確定する。
3. 通常モード既存ファイルの変更有無を確認する。
4. 承認済み共通UI境界以外の通常モード既存ファイル変更が必要なら、実装せず停止する。
5. Stem専用候補選択層を処理経路から除去する。
6. 通常モードの一本道へ接続するStem専用adapter、状態、保存、UIだけを実装する。
7. 1回の論理工程ごとに、実装と直接関係するテストを実行する。
8. 検証に失敗した場合は原因をコード、ログ、実測から特定し、推測のfallbackを追加しない。
9. 通常モードの音質処理へ未承認差分がないことを各工程で確認する。
10. ビルド成功、テスト成功、実画面成功、実モデル成功、実音確認を別々の事実として記録する。
11. 現在のworktreeで完了根拠を確認できた項目だけ、進捗チェックリストへ`[x]`を付ける。
12. コードが存在するだけ、または過去にテストが成功しただけでは完了にしない。
13. 実装、設計、構成を変更した場合だけ`FOR[hazimeno_ipoo].md`を更新する。
14. 各工程後に`git diff --check`と対象差分レビューを行う。
15. ユーザーの未コミット変更を削除、上書き、復元しない。
16. サブエージェントを使用しない。
17. 1ターンにつき、検証可能な1つの論理工程を進める。
